# Ozon rFBS: остатки и статусы заказов

Программа для Windows (`OzonRFBS.exe`). Она подключается к магазину Ozon через Seller API и ведёт заказы rFBS по статусам за курьеров:

1. **Собрать** — как только пришёл целевой заказ.
2. **Доставляется** — через паузу, по умолчанию 1 минута.
3. **Курьер в пути** — ещё через паузу.
4. **Условно доставлен** — как можно позже: за 3 минуты (настраивается) до конца окна доставки, которое Ozon указал для заказа.

Ещё программа выставляет одинаковый остаток двум SKU на выбранном складе.

## Какие заказы обрабатываются

Только **целевые** отправления. Должно выполняться всё сразу:

- склад отправления — выбранный;
- в отправлении ровно 2 позиции, это два указанных SKU, по 1 шт. каждой.

Остальные заказы программа не трогает. Они видны в блоке «Пропущенные заказы» с причиной. Отменённые заказы и заказы в арбитраже тоже не трогаются.

## Скачать

**Последняя версия:** [OzonRFBS.exe](https://github.com/digushok/rfbs/releases/latest/download/OzonRFBS.exe). Все версии и что в них нового — в разделе [Releases](https://github.com/digushok/rfbs/releases).

Обновление: закройте программу (⏻), замените `OzonRFBS.exe` на новый и запустите. Настройки и ключи сохраняются. Проверить, есть ли новая версия, можно в самой программе: «Настройки → О программе → Проверить обновления».

## Установка и запуск

1. Скопируйте `OzonRFBS.exe` в любую папку и запустите. Откроется окно программы в браузере, адрес `http://127.0.0.1:8766`.
2. Программа работает, пока запущена. Закрытие вкладки браузера её **не** останавливает. Повторный запуск `.exe` просто откроет окно снова. Выход — кнопка ⏻.
3. Если автоматизация была включена, после перезапуска программы она продолжит сама. Можно добавить `.exe` в автозагрузку Windows.
4. Windows SmartScreen может предупредить о неизвестном издателе: «Подробнее» → «Выполнить в любом случае».

Данные хранятся в `%APPDATA%\OzonRFBS`: настройки магазинов и ключи, журналы заказов, логи. Они не пропадают при замене `.exe`.

## Первая настройка

1. **Настройки → Магазин**: Client-Id и API-ключ. Ключ создаётся в кабинете Ozon: Настройки → Seller API. Нужные роли: **Posting FBS** и **Stocks** (или **Product**). Нажмите «Проверить подключение».
2. **Заказы → Склад и товары**: нажмите ↻, выберите склад, укажите два SKU Ozon, нажмите «Сохранить». Под полями появятся названия товаров и текущие остатки.
3. Магазинов может быть несколько: «Настройки → Магазины на этом компьютере». Переключение — в правом верхнем углу. Автоматизация каждого магазина работает независимо.

## Тестовый режим (обязательно перед боевым)

Новый магазин всегда создаётся в **тестовом режиме**:

- программа читает **настоящие** заказы из Ozon;
- все изменяющие запросы (остатки, «Собрать», смена статусов) **заблокированы на уровне клиента API** и только пишутся в журнал с пометкой `[ТЕСТ]`;
- шаги симулируются, поэтому в таблице «Целевые заказы» видна вся цепочка с реальными временами: когда программа собрала бы заказ, перевела бы в «Доставляется» и «Курьер в пути», и **когда именно** перевела бы в «Условно доставлен».

Что проверить в тесте:

- в «Целевые заказы» попадают нужные заказы, а в «Пропущенные» — все остальные;
- **окно доставки** в таблице совпадает с таймслотом заказа в кабинете Ozon;
- время «Условно доставлен» = конец окна минус 3 минуты.

Кнопка «Сбросить тестовый прогон» забывает симулированные шаги, и тест начинается заново.

Есть ещё **демо-магазин**: полностью встроенный имитатор Ozon без ключей. Он генерирует заказы, в том числе нецелевые, с коротким окном доставки около 10 минут. Это удобно, чтобы посмотреть всю цепочку целиком, в том числе в боевом режиме.

## Боевой режим

Переключатель «⚡ Боевой режим» (с подтверждением), затем «Запустить». С этого момента статусы и остатки меняются в Ozon по-настоящему.

Особые случаи:

- **Окно доставки уже закончилось**, например компьютер был выключен: «Условно доставлен» ставится сразу, в журнале будет предупреждение.
- **Ozon не вернул окно доставки**: шаг «Условно доставлен» не планируется, заказ подсвечивается предупреждением. Переведите его вручную.
- **Ошибка Ozon**: запрос повторяется при следующем опросе, ошибка видна в таблице и журнале. Если «Курьер в пути» не принимается 3 раза подряд (например, статус уже выставили вручную), программа считает шаг выполненным и ждёт конца окна.
- **Запросы покупателя на отмену** программа не обрабатывает.

## Ограничения, о которых стоит знать

- **Компьютер должен работать.** Пока программа закрыта или компьютер выключен, статусы не меняются. Если окно доставки успело закончиться, программа после запуска сразу поставит «Условно доставлен», но с опозданием. Сон Windows программа блокирует сама, пока включена автоматизация, а выключение и перезагрузку — нет.
- **Один магазин — один компьютер.** Не запускайте автоматизацию одного магазина на двух компьютерах одновременно: они будут дублировать запросы.
- **Остатки выставляются один раз.** При большом потоке заказов остаток закончится, и новые заказы перестанут приходить, пока вы не выставите его снова.
- **Запас 3 минуты.** Если у сотен заказов один конец окна, а Ozon в этот момент ограничивает частоту запросов или отвечает с ошибками, запаса может не хватить. Программа шлёт статусы пачками и срочные первыми, но запас можно увеличить в настройках.

## Параметры (Настройки → Параметры автоматизации)

| Параметр | По умолчанию |
|---|---|
| Пауза между шагами | 60 сек |
| Запас до конца окна доставки | 3 мин |
| Опрос Ozon | каждые 30 сек (и точно в момент запланированного шага); запрашиваются только заказы в рабочих статусах |
| Глубина просмотра заказов | 14 дней (заказ, созданный раньше и ещё не доставленный, перестанет обрабатываться — увеличьте, если окна доставки бывают дальше) |

## Используемые методы Ozon API

| Действие | Метод |
|---|---|
| Список заказов склада по статусам (с окном доставки `analytics_data.delivery_date_begin/end`) | `/v4/posting/fbs/list` |
| Перепроверка одного заказа | `/v3/posting/fbs/get` |
| Собрать | `/v4/posting/fbs/ship` |
| Доставляется / Курьер в пути / Доставлено | `/v2/fbs/posting/delivering`, `/v2/fbs/posting/last-mile`, `/v2/fbs/posting/delivered` |
| Остатки | `/v2/products/stocks`, `/v2/product/info/stocks-by-warehouse/fbs` |
| Товары по SKU | `/v3/product/info/list` |
| Склады | `/v2/warehouse/list` (запасной вариант — `/v1/warehouse/list`) |
| Проверка ключа | `/v1/roles` |


```bash
go test ./...
```

## Версии и релизы

- Номер версии хранится в файле `VERSION`, список изменений — в `CHANGELOG.md`.
- При каждом пуше GitHub Actions прогоняет тесты и собирает `.exe`.
- В основной ветке, если релиза с такой версией ещё нет, он публикуется автоматически: тег `vX.Y.Z` и файл `OzonRFBS.exe`.
- Как выпустить новую версию: поднимите номер в `VERSION` (например, `1.0.1` — исправления, `1.1.0` — новые возможности), добавьте раздел в `CHANGELOG.md` и запушьте.

Структура:

- `ozon.go` — клиент API;
- `worker.go` — логика статусов;
- `mock.go` — демо-Озон;
- `store.go` — хранение данных;
- `api.go` и `static/` — интерфейс.
